# Marin Budget

Marin Budget is the County of Marin budget and Capital Improvement Plan. It opens on a Dashboard: a look at the Budget and the Capital improvement plan, each with a link to its pages. It is a static, zero-build MarinOS docs-shell application and follows `marin-digital-standards`.

## Structure

- `index.html`: the Dashboard (`scripts/build-dashboard.js`). Its figures come from the same data as the pages it links to.
- `budget/`: the Budget (FY 2026-28 book), its service areas, departments, funds and the Compare tab of the Budget tool (pick two to four departments: charts and a table, picks in the address as `?tab=compare&compare=sheriff,probation`), and `budget/fy2025-26/`, the FY 2025-26 Final Budget — see "Budget" below
- `capital/`: the Capital improvement plan, its projects and a page for each project — see "Capital improvement plan" below
- `data/`: `organizations.jsonld` and `programs.jsonld`, copied from marin-data, for names and links
- `shared/`: scripts and styles shared by the pages (`page-data.js`, `insights.js`, `search-layout.js`, `app-home.js`, `styles.css`)
- `scripts/`: the page generators and `check.sh`
- `vendor/`: the installed MarinOS App Shell (`vendor/marinos/`), its fonts, icons and Chart.js

Every page uses the MarinOS app shell (`marin-app-header`, `marin-app-info` with About, Security, Accessibility and Updates, `marin-app-footer`, `marin-app-feedback`), written by `scripts/budget-shell.js`; `shared/app-home.js` points the header title at the app's home page from any folder. The tabs of every page are Dashboard, Budget and Capital improvement plan. Pages for organizations, service areas and programs are in [Marin Docs](https://marincountygov.github.io/marin-docs/); links to them are absolute, and the Budget tab on those pages reads the same data from marin-data.

## Data

All figures come from [marin-data](../marin-data), which reads the County's books (`extract_budget.py`, `extract_budget_2025.py`, `extract_cip.py`). Nothing here is written by hand. To rebuild every page from `../marin-data/output`:

```sh
bash scripts/build-all.sh            # or: bash scripts/build-all.sh <folder with the files>
```

That copies `organizations.jsonld` and `programs.jsonld` into `data/`, then runs `build-budget.js`, `build-budget-2025.js`, `build-capital.js` and `build-dashboard.js`, in that order. Edit the data or the generators, never the generated pages.

## Capital improvement plan

The Budget and Capital sections show the TEST banner (`project.test_sections` in `marin.yml`, written by `scripts/test-banner.js`); remove a section from that line when its data has been reviewed.

`capital/` is built from schemaGov JSON-LD, not written by hand. The data is in `capital/data/`: `cip-projects.jsonld`, `cip-budgets.jsonld`, `cip-budget-lines.jsonld`, `cip-display.json` (category, the book's New or Ongoing status, prior approvals, additional funds needed, page numbers and the book's printed totals, which schemaGov has no property for) and `sources.json`. `marin-data/extract_cip.py` makes them from the County's FY 2027-31 CIP book. Run `node scripts/build-capital.js ../marin-data/output/cip` to copy new data in and rewrite `capital/index.html`, `projects.html` and a page for each project (`capital/projects/<name>.html`); then run `node scripts/build-budget.js` so the capital funds link to the plan. Figures are whole dollars as the book prints them; every page cites its book pages. The landing page shows the plan's totals by category and year and the fund sources. The Projects page is a tool (`capital/projects.js`, with the shared `shared/search-layout.js`): a filter column (search, categories, subcategories, statuses, funded years, cost estimates, funding gaps), a bold "Showing:" line, live stats for what is selected on a Stats tab (projects, cost estimate, funding in the plan, additional funds needed, three charts drawn with Chart.js that redraw as the filters change, and the tables behind them), a Data tab with the sources and a Notes tab (notes from `capital/data/sources.json`, and the listed projects checked against the book's printed subtotals), sort buttons, and a switch between cards and a table. Every project is in the page twice, as a card and as a table row with its figures in data attributes, so the page works as a plain list without the script; the script hides what does not match and recomputes the stats, and Copy and Download hold the selection. Filters, sort and view are kept in the address (`projects.html?category=Facilities&status=New&view=table`). Each project page shows its funding by year. The book names no department or fund for a project, so none is shown; fund sources are for the plan as a whole. Where a category's projects do not add up to the total the book prints (Civic Center), the page says so and shows both. Only the five-year plan is shown; the plan has no Insights tab yet. `BudgetLine.project`, which ties a line to its project, is proposed for schemaGov and is not in its schema yet.

## Budget

`budget/` is built from schemaGov JSON-LD, not written by hand. The data is in `budget/data/`: `funds.jsonld`, `sources.json`, `budgets.jsonld`, `budget-lines.jsonld` and `source/budget-display.json` (the book's printed change columns, FTE, net County cost and page numbers, which schemaGov has no property for). `marin-data/extract_budget.py` makes the budget files from the County budget book. Run `node scripts/build-budget.js ../marin-data/output` to copy new data in and rewrite `budget/index.html`, `service-areas.html`, `departments.html` and `funds.html`. A department's Budget tab is on its page in Marin Docs, which reads the same data from marin-data. `scripts/budget-data.js` builds the tables. Figures are whole dollars as the book prints them, with the book's own column headings (FY 2026-27 is still headed Proposed in the final edition); every table cites its pages and links to the book. FY 2027-28 (planned) is not shown. Each fund has a page (`budget/funds/<code>-<name>.html`) with About, Data and Insights tabs; the General Fund, the one fund the program rows name, also has a Budget tab by department. Fund cards link to them, and a program's General Fund row links to its page. The Budget page opens with the County as a whole (printed pages 20 and 21): total expenditures and revenues, the change, the use of fund balance, pies by type, a table, and the General Fund and HHS Operating Fund together. The Program Overview is read too: each program row is a budget line with its fund group, and rows that are one of the programs in the data (by name or `marin-data/program-aliases.json`) carry `program`; the service area and program pages, in Marin Docs, show their Budget tabs from the same lines. Every table (`table()` in `scripts/budget-data.js`, used on the budget, organization, service area, program, fund and capital pages) has its own Copy and Download buttons above it: Copy as text, HTML or Markdown, and Download as the same or as a CSV with figures as numbers, read from the table itself so it always matches the page. The budget tables have charts above them (Chart.js, `vendor/chart.min.js`), drawn by the shell from amounts written into the page, so a chart and its table always come from the same figures (`chart()` in `scripts/budget-data.js`; the page test compares them). A department's Budget tab appears only when the book has figures for it; the County itself has none yet, and funds are not linked to departments.

`budget/fy2025-26/` is the County's FY 2025-26 Final Budget book, kept apart from the FY 2026-28 book above (its figures are the Recommended and Adopted ones as first printed, so they are not merged with the later book's "Approved"). The book's schedules are read row by row, not by department: `marin-data/extract_budget_2025.py BOOK.pdf output --cache pages.pkl` writes `budget-2025-26/schedules.json` (all fifteen schedules, the Road Fund work program, personnel allocation by department and by fund, and the property tax trends, each row with its label, code, figures and PDF page), the schemaGov files `budgets-2025-26.jsonld`, `budget-lines-2025-26.jsonld` and `funds-2025-26.jsonld`, and `qa/budget-2025-26-checks.json`. The run fails if a total the book prints differs from its parts (a dollar or two of the book's own rounding is allowed and listed). Run `node scripts/build-budget-2025.js ../marin-data/output` to copy the data into `budget/fy2025-26/data/` and write an overview, a page for each schedule (a section for each fund or budget unit on the long ones), `road-fund.html`, `personnel.html` and `property-tax-trends.html`. The FY 2025-26 Final Budget is also on the Budget tab of each department that has a budget unit in the book and of each fund the book prints (`scripts/budget-2025-org.js`): the unit's lines by function and activity, its revenues and expenditures by object (Schedule 9) and its personnel allocation FTE for a department, and Schedules 2 and 3 for a fund, in the book's own columns and kept apart from the FY 2026-28 figures above them.

The home page of each book (`budget/index.html`, `budget/fy2025-26/index.html`) is the same tool, built by `scripts/budget-tool.js` and run by `budget/tool.js`, with the book's own columns, filters and lines given as JSON in the page: a filter column (a Budget choice of book, the latest first and chosen on its own page, each book being its own page; a Year choice; search and the book's facets), the tabs Budget, Stats, Data and Notes, a Year filter in the filter column (radio buttons: which year's amount the cards, stats and charts show; the table shows every column), sort, cards or table, and Copy and Download for what is selected. Tags on a card are badges, not buttons; filtering is in the filter column. For FY 2025-26 the lines are the Schedule 8 budget unit lines and the filters are function, activity and budget unit; for FY 2026-28 the lines are departments and divisions, filtered by service area, department and type. Under Stats the County as a whole follows the selection's stats. Data lists the schedule pages and the JSON files, and Notes is written from `budget/fy2025-26/data/notes.json`, which the extractor makes from what it found (the notes, totals that differ from their parts, budget units with no organization, unreadable cells). Printed page number = PDF page number - 8. The book's PDF is in `marin-data/source/` and its web address is `budgetBook2025.url` in `marin-data/output/sources.json`; every cited page number links to that page of the PDF. Four cells in Schedule 4 are printed over each other in the PDF and are left empty and listed in the QA file.



## Login screen

Every page loads `shared/gate.js` first. Until the password is entered in the tab, the page is hidden and a password form shows; the choice is kept for the tab (`sessionStorage`). Only a SHA-256 hash of the password is in the file. To change the password, replace `HASH` with `printf '%s' NEWPASSWORD | shasum -a 256`. This is a gate in the browser, not access control: the pages and data files are static files and can be requested directly. `security.json` says so.

## Run locally

From the repository root, run `python3 -m http.server 8765 --bind 127.0.0.1`, then open `http://127.0.0.1:8765/`.

## Checks

`bash scripts/check.sh --browser` also runs `tests/browser_budget.py` (Playwright for Python and Google Chrome or Chromium): the Dashboard, About, the header link, the Stats overview and sort, Compare departments, the capital Stats totals and the gap sort, and phone width.

`bash scripts/check.sh` checks the shell install, the button audit, the generator scripts, `tests/budget-data.test.js` (the budget lines against themselves), `tests/test_generated.py` (language, titles, one h1, links and files, the Dashboard and tabs, and the charts against the data) and `tests/test_budget_pages.py` (the budget and capital pages against the books' own checks).
